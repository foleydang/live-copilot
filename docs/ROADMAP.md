# 产品路线图

## 当前状态：POC v0.2

- ✅ 多租户、多房间、抖音/视频号双平台
- ✅ LLM + 本地规则降级、FAQ RAG、违禁词护栏
- ✅ 串行 worker 队列 + httpx 连接复用
- ✅ TTS 缓存 + LRU 清理
- ✅ 留痕 + 效果度量（AI 承接率 / 延迟 / 知识库缺口）
- ✅ 一键静音、租户用量计量
- ✅ 安全加固 + 限流 + logrotate
- ⏳ 未填直播间号、未装采集器（douyinLive）
- ⏳ TTS 还是 mock（未接 CosyVoice）
- ⏳ 无 HTTPS、无域名

## 下一个里程碑：v1.0（前 3 个付费客户）

**目标**：能稳定跑 1~3 家客户，每家用 1 个月不出问题。

### 必做

- [ ] 配 HTTPS（`live.yanten.top`）+ nginx 反代
- [ ] 装 douyinLive 采集器并做 systemd 守护（`deploy/douyinlive.service`）
- [ ] 接 CosyVoice TTS，预热 FAQ 语音
- [ ] 非 root 用户运行（`aizhubo`）
- [ ] 客户扫码即开：二维码生成脚本（`tools/qrcode.py`）
- [ ] 监控：UptimeRobot 打 `/api/health`，异常发邮件
- [ ] 用量计费：每租户 token 月度上限 + 80% 预警 + 100% 降级

### 应做

- [ ] 小程序"控制端"（配置 / 看板 / 静音，不播音频）
- [ ] 留痕按 `room_id + 开播时间` 命名（而非 PID）
- [ ] `/api/admin/metrics`：汇总所有租户用量、错误率
- [ ] 开播自动口播 + 每 30 分钟复播 AI 声明（合规加强）

## v1.5（10+ 客户）

- [ ] 按租户隔离日志目录（已实现，但加目录配额）
- [ ] 支持多音色 per 租户（已实现 `voice` 字段，未暴露 UI）
- [ ] 知识库版本管理（回滚到昨天的配置）
- [ ] 客户自助续费 / 账单（微信小程序 + 微信支付）
- [ ] 抖音电商罗盘数据对接（GMV / 转化率）→ 算 AI 承接对成交的贡献

## v2.0（产品化）

- [ ] 多进程：每个租户独立进程（隔离故障 + 独立扩缩）
- [ ] 容器化：Docker image + k8s / 阿里云 ACK
- [ ] 管理后台（运营者用，不是店主用）：租户管理、用量看板、计费
- [ ] 视频号合规模式（已实现 `assist_voice:false`，需要 UI 引导）
- [ ] 多语言（海外 TikTok 客户）

## 长期可能做

- [ ] 直播间数据对接：把"AI 承接率"和"转化率"关联，做 A/B 验证
- [ ] 智能 FAQ 推荐：从历史弹幕自动提取"观众在问什么"，推荐给店主补知识库
- [ ] 多主播协作：同一客户多个助播账号（主号 / 助手号 / 客服号）

## 声色模拟合成（计划中）

接入 TTS 声音克隆，让 AI 助手用主播自己的声音说话：

- **声音采样**：主播录制 30 秒音频，提取声纹特征
- **实时合成**：阿里云 CosyVoice / 本地 VITS 模型
- **效果**：观众听到的 AI 回答和主播声音一致，体验更自然
- **依赖**：需要 GPU 推理或云端 API 额度

当前状态：已预留接口，待 TTS 服务接入。
